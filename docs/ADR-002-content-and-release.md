# ADR 002: local content and exact-package release

Accepted 2026-10-04 after the single Claude plan review and Codex dispositions R-25–R-35.

Use declarative version-1 JSON packages and hand-written typed validators. No executable schema compilation, imported scripts, HTML, or external assets. Fixed pilot teaching sequences remain intentional; arbitrary graphs and construction tasks are outside this phase. Comparison packages share the positive integer 1–100 domain. Angle rotations are bounded; arm lengths are renderer constants. Candidate curriculum evidence can cite third-party providers and historical papers.

Literal task wording, hints, explanation choices and reflection cannot be proven by model consistency. Validation reports that warning, including when a model edit leaves literal prose stale. Bounded generation regenerates wording from parameters, but also requires human review. Source spans prove only exact text linkage. Mathematical fixtures and independent generator checks do not certify pedagogy.

The version-1 digest is SHA-256 of canonical JSON: recursively sorted object keys, ordered arrays, JSON scalar encoding, finite numbers only. The frozen empty-object vector is tested. Every package field, including curriculum, authors, generation provenance, interpretation, teaching, visual specification and fixtures, is content-bound. Changing generator version even with identical prose intentionally requires renewed review. No review envelope is accepted inside packages. Review evidence lives separately in release/reviews.json; reviewer authority lives in release/reviewers.json. There are no external asset references in this version; adding them requires a new asset-bound contract.

The release manifest binds ID, version and digest plus the application contract and a recorded content-impact decision. The local maintainer verifies the actual origin and qualification of reviews; the tooling requires two distinct qualified humans, independent of authors, approving the exact digest and disposing of warnings. These local files are publisher-controlled records, not a cryptographic identity service. Synthetic test records grant no real publication authority.

The learner build validates manifest packages before generating its virtual module. It imports only the allowed lesson data and has its own entry, without catalogue imports or author code. Build-time validation is the primary gate; the runtime separately checks the embedded package structure, identity and digest before opening lessons. Empty release manifests produce an explicit no-approved-content page. Keep prior verified build artifacts externally for rollback; automatic artifact archiving/deployment is not implemented.

Node artifact checks verify separation independently of browser permissions. DOM tests establish interactions, not layout/accessibility. Nonvisual angle-arm directions describe a different route to reasoning than visual comparison and remain a human accessibility/pedagogy review item. Introductory generator distractors are curated; near-miss fixture cards remain in the original catalogue. These choices are candidates, not certified curriculum decisions.
