# ADR 008 — Playful P4 practice and deterministic variants

Date: 2026-10-06. Status: implemented for the development preview at the user's instruction. The user explicitly waived Claude's engineering review for this phase; no Claude review is claimed.

The generic lesson layout put too much introductory material before the active task on phones and did not carry the home's playful character. Learners also needed fresh variables for practising the same method rather than replaying a fixed question.

Keep the existing runtime and exact topic assessment. Add compact P4 styling and decimal/fraction workbenches, with selectable alignment examples and mathematical overlays controlled by assessed goals or explicit hint disclosure. Preserve author edit anchors, frozen trials, guided mode and the approved palette/fonts. A solved fraction calculation displays an unreduced common-partition result until the simplest-form goal is solved or explicitly revealed.

Use pure P4 teaching builders shared with author rewrites. Eight narrowly bounded generation profiles enumerate integer tuples, exclude the source tuple, apply a versioned seeded permutation and visit each tuple once. Recognition requires the complete canonical starter payload and an explicit skill signature. Unknown or edited packages are ineligible; invalid candidates preserve the current completed example. Exhaustion and set restart are explicit. Different runs assign different instance IDs while the seed reproduces numerical parameters, choices and teaching text; source/template versions and generator version are part of reproducibility context.

Keep the generator imported only by development composition. Approved learner builds receive the shared presentation but no generator dependency or callable generation capability. Saved JSON packages, library index, release manifest and schema/application contracts remain unchanged. Generator-wide approval is deferred; no generated variant inherits approval from its source. New presentation and builder changes require content-impact assessment when real publication begins.

An in-memory journal retains the latest 20 ended attempts with support/facilitator categories, variant metadata and repeated-example context. It upserts completion to account for later adult reveals and captures attempts before navigation or replacement. New attempts have fresh answer/hint state and preserve selected mode. Source results remain separate from variants, routes remain bound to source IDs and variants do not advance the mixed-set cursor. Refresh resets temporary practice to the original source.

Implementation tradeoff: `src/ui/p4-activity.ts` is a bounded UI helper directly composed by the shared view instead of adding a new topic-presentation registration contract now. The pure core runtime still imports no concrete topics. Unsupported topic/goal sequences fall back to existing renderers. Rich workbenches currently cover decimal add/subtract and fraction add/subtract; other P4 forms retain diagrams with compact styling. Direct placement/drag tasks, adaptive difficulty/fading, author variant saving, persistence and publication policy are deferred.

Verification: full unit/DOM suite passed 515 checks across 29 files, followed by 6/6 preview integration checks including a new complete exhaustion/restart trace. Both builds, typecheck, lint, formatting, 45-package validation and synthetic release/artifact gates pass as recorded in the handover. Generator tests sweep all profile domains using independent mathematical predicates. Browser startup failed with sandbox EPERM, so no new screenshot inspection, layout/device/zoom or assistive-technology pass is claimed. The static design mock remains under `docs/design/` for later host inspection.
