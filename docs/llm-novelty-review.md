# Review of the LLM novelty plan

**Status: written on 2026-10-11 by an independent reviewer agent (Claude) that did not write the plan.** This is a review, not a decision. Codex, or the user while Codex is unavailable, still has to record accept, modify, reject or defer for each finding. It approves no lesson content, and no human has reviewed anything. Reviewed: `docs/llm-novelty-plan.md` against `src/practice/generation.ts`, `src/content/p4-{decimal,fraction}-builder.ts`, `src/ui/lesson-view.ts`, `src/ui/p4-activity.ts`, `src/ui/visuals.ts`, `src/content/lessons.ts`, `src/content/package-validation.ts`, `vite.config.ts`, `scripts/annotation-dev-plugin.ts`, `src/annotation/{handler,anthropic-call}.ts`, `scripts/check-learner-artifact.mjs`, `package.json`, the installed Vite 7.3.6 source (`node_modules/vite/dist/node/chunks/config.js`), handover decision 23, SOW §6.2, and the aura-health reference (`aura_app/system_settings.py`, `aura_communication/vendor.py`). The compass reference was only skimmed. Anthropic model facts come from the bundled Claude API reference (cached 2026-09-25).

## Verdict

**PROCEED WITH THE CHANGES BELOW.** The security core (write-only keys, an owner-only data root outside the repository, a timing-safe token, budgets reserved before each call, fail-closed fallback to deterministic variants, no learner data in prompts, a model-free learner build) is sound and follows aura-health closely. But five things must change before WP1 or WP3:

1. **Value (R-111).** The plan's main finding is understated. For all three first-wave profiles the enumerated domain is *exactly* the predicate, so a model-proposed specification can add no mathematical novelty at all. `p4-fraction-of-quantity` has only 7 specifications (3/4 of 16 to 40 counters). For "more novel examples", widening the deterministic profiles and adding a reviewed bank of story frames gives more for less money and risk. The user should see this trade-off before money is spent on the LLM path.
2. **Hosting (R-112).** Port 5178 runs `npm run dev`, not `vite preview`. The server pipeline cannot run in `vite preview` as specified, because `packages` depends on `import.meta.glob`.
3. **Free story text (R-113).** A free-text story can contradict the mathematics (an "adds" story on a subtract-only profile), and number words can leak through. Deterministic checks cannot catch either.
4. **Choice labels (R-114).** Letting the model write `choiceLabels` means it writes the correct option and the distractors, which is answer authoring.
5. **Unreviewed text shown at once (R-115).** Showing unreviewed model text straight to the child, by default, conflicts with SOW §6.2 and with the R-65 precedent. An adult-approved pool solves this and also removes the unauthenticated LAN endpoint.

## Confirmed claims (verified true)

- Generation covers exactly the eight canonical starters, is `p4-bounded-v1`, is preview-only, and refuses edited starters (`starters` map plus `canonicalJson` comparison).
- Generated wording is fixed templates. `rewriteDecimalLesson` sets the story "Calculate with equal place units and check the result." The builders have no context parameter.
- `VariantDescriptor` lives in `src/practice/generation.ts` and is runtime-only. An optional field is additive. Variant attempts never set the source's completion label (`main.ts` 34 and 152, `!summary.variant`). No package-schema or contract bump is needed, because package validation already accepts `generated` provenance (subject to R-125).
- `configurePreviewServer` exists in Vite 7.3.6 (but see R-112). In both servers, Vite's CORS and host-validation middlewares run before plugin middlewares.
- `npm run dev` and `npm run preview` both bind `0.0.0.0`. The annotation plugin is `apply: "serve"` and loopback-only, with a header and an Origin check.
- The aura-health pattern is as described: the directory is 0700, the token is created exclusively at 0600, writes go to a temp file then `fsync` then `os.replace`, Bearer tokens are compared with `compare_digest`, there are 20 failed unlocks per minute then 429, exact field sets, `revision` is new hex on every write, enable is refused without a key, the paid test needs a confirm string, `follow_redirects=False` and `trust_env=False`, responses are capped at 1 MB for `/models`, and discovery is filtered by word list. The model-id regex is identical.
- The Anthropic request shape matches `src/annotation/anthropic-call.ts` (beta `messages.create`, `fallbacks: "default"`, `output_config.effort: "low"`, `max_tokens` 4000). Opus 5.5 list prices are $4/$20, matching the plan.
- `@anthropic-ai/sdk` 0.131.0 is a dev dependency. No new dependency is needed.
- `.gitignore` already ignores `.env*` and allows `.env.example`.

## Unverifiable items (not confirmed by me)

- Live provider behaviour: structured output on each Anthropic model (including whether Haiku 4.5 accepts `output_config.format`), OpenAI strict `json_schema`, OpenRouter `json_object`, real token counts and latency, and refusal rates for children's story prompts.
- Whether OpenRouter honours `store: false` or data-retention settings. This is provider policy.
- Whether undici `fetch` ignores proxy environment variables on every Node 22 minor version. Node 22.21+ has opt-in `NODE_USE_ENV_PROXY`. The plan should assert that it is unset.
- The compass reference: skimmed only, so its behaviour is not checked against the plan.
- Child-suitability of any wording, names or blocklist. This needs a human reviewer, and no test can establish it.
- Domain counts (7, 50, 8,505) were computed by hand from the loops, not by running the code.
